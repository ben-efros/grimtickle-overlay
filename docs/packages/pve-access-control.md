## What it provides

Role-based access control for all of Proxmox VE:

- `PVE::AccessControl` — user/group/realm/permission engine
- `PVE::RPCEnvironment` — per-request auth context wired into the HTTP server
- `PVE::TokenConfig` — API token CRUD
- `PVE::Auth::*` — realm backends: PAM, PVE (local), LDAP, AD, OpenID
- `PVE::API2::*` — REST endpoints: `/access/users`, `/access/groups`, `/access/roles`, `/access/acl`, `/access/domains`, `/access/tfa`, `/access/ticket`, `/access/openid`
- `PVE::CLI::pveum` — CLI front-end (`pveum`)
- `PVE::Jobs::RealmSync` — scheduled LDAP/AD sync job

## Gentoo-specific Changes

### ❌ `libpve-cluster-perl` not yet ported (DEFERRED)
`PVE::AccessControl` reads all user/group/realm/ACL data from `/etc/pve/user.cfg`
via `PVE::Cluster::cfs_read_file()`. Without pmxcfs, pvedaemon cannot authenticate.
**Workaround:** mount `/etc/pve/` as a plain directory and seed it with a minimal
`user.cfg` (see below).

### ⚠️ Shell completions skipped (DIFFERENT)
`pveum.bash-completion` and `pveum.zsh-completion` are generated at build time by
running `PVE::CLI::pveum->generate_bash_completions()`, which requires the full runtime
dep stack. We skip generation to avoid a circular BDEPEND on `libpve-cluster-perl`.

### ⚠️ Man page skipped (DIFFERENT)
`pveum.1` is generated by `pve-doc-generator` (not yet ported). The `pveum` binary
still functions; the man page is missing.

## Single-node Bootstrap (no pmxcfs)

To allow pvedaemon to start on a single node without a running `pmxcfs`:

```bash
mkdir -p /etc/pve/priv
cat > /etc/pve/user.cfg <<'EOF'
user:root@pam:1:0:::root@localhost::
EOF
touch /etc/pve/priv/shadow.cfg
```

This creates a minimal user database with root@pam as the only user.
Full ACLs and additional realms can be added later through the API or UI.

> Note: this is a **temporary workaround**. Once `libpve-cluster-perl` is ported,
> pmxcfs will manage `/etc/pve/` and these hand-crafted files will be superseded.
